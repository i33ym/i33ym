Security from the Metal Up

How to make attackers regret choosing your server

Isroil Muhitdinov · February 2026

Right Now, a Bot Is Trying

ssh root@your-server

password: admin


This started 45 seconds after your IP was assigned.

The Plan

Server → Docker → Network → Application → Authorization → Secrets → Dependencies → Monitoring


Each layer assumes the one above already failed.

🔒 The Server Layer

SSH: No Passwords. Ever.

PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
AllowUsers deploy
MaxAuthTries 3

+ fail2ban = bots get banned in 3 tries

Least Privilege

# Not this
deploy ALL=(ALL) NOPASSWD: ALL

# This
deploy ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart myapp

chmod 600 your secrets. "Only I use this server" is famous last words.

Firewall: Default No

ufw default deny incoming
ufw allow 22/tcp
ufw allow 443/tcp
ufw allow 80/tcp

If Postgres doesn't need internet access, don't open 5432. Be rude.

🐳 Docker Security

Containers Run as Root by Default

Let that sink in.


USER app  # add this to your Dockerfile

Two words. Problem solved.

The Docker Group Is Root in Disguise

docker run -v /:/host -it alpine sh
cat /host/etc/shadow   # full host access

Use rootless Docker or Podman instead.

🌐 Network Layer

Make SSH Invisible

# Tailscale/WireGuard VPN, then:
ufw allow from 100.64.0.0/10 to any port 22
ufw deny 22

Port scanners find nothing. Bots go home confused.

💻 Application Layer

(where the real fun begins)

Trust Nobody

class CreateUser(BaseModel):
    name: str = Field(min_length=1, max_length=100)
    email: EmailStr
    age: int = Field(ge=13, le=150)

Server-side validation. Client-side is decoration.

SQL Injection: Still Happening in 2026

# 😱
f"SELECT * FROM users WHERE name = '{user_input}'"

# 😌
cursor.execute("...WHERE name = %s", (user_input,))

XSS

User submits: <script>stealCookies()</script>

Your template renders it. Everyone's session is gone.


Jinja2 auto-escapes. Never use | safe on user content.

Auth Checklist

✅ argon2/bcrypt (slow = good)

✅ HttpOnly + Secure + SameSite cookies

✅ JWTs in cookies, never localStorage

✅ Rate limit login: 5/min/IP

Security Headers: Free Armor

Content-Security-Policy: default-src 'self'
Strict-Transport-Security: max-age=31536000
X-Frame-Options: DENY
X-Content-Type-Options: nosniff

Six lines of Nginx config. Blocks entire attack classes.

🔑 Authorization

(the part everyone gets wrong)

The Broken Pattern

if user.role == "admin":
    allow()
elif user.role == "editor" and resource.owner == user.id:
    allow()
# ... 40 endpoints later, nobody knows who can do what

Fine-Grained Authorization

# OpenFGA model
type document
  relations
    define owner: [user]
    define editor: [user] or owner
    define viewer: [user] or editor

One model. Query from anywhere. No scattered if-statements.

Check Permissions, Not Roles

# Can john edit this?
check(user="user:john",
      relation="editor",
      object="document:security-essay")
# → false

Adding a role = model change, not a 40-file code change.

IDOR: The Dumb Bug

User hits /api/invoices/42

Changes to /api/invoices/43

Is that their invoice? Did you check?


Every ID-based endpoint needs ownership verification.

Row-Level Security

ALTER TABLE documents ENABLE ROW LEVEL SECURITY;

CREATE POLICY docs_owner ON documents
    USING (owner_id = current_setting('app.user_id')::int);

Even if your app has a bug, the database won't leak rows.

🔐 Secrets

L1: sops + age (encrypt in repo)

L2: GCP Secret Manager (never on disk)

L3: Vault (short-lived, auto-rotating)


None protect a fully compromised runtime.

📦 Dependencies

90% of your app is someone else's code.


event-stream (2018): stolen Bitcoin wallets

colors/faker (2022): self-sabotage


Pin versions. Commit lockfiles. Audit regularly.

👁️ Monitoring

"Hope" is not a security strategy.


Ship logs off-server. Alert on anomalies.

Have an incident playbook: isolate → preserve → rotate → patch → restore.

The Mental Model

Every layer assumes the one above already failed.


The goal: make attacks expensive enough that the attacker goes to bother someone with an open MongoDB on port 27017.

One Last Thing

Security is not a product.

It's a practice.


Like testing, like code review, like not deploying on Fridays.
