Security from the Metal Up

How to make attackers regret choosing your server

Isroil Muhitdinov · February 2026

Right Now

A bot is trying:

ssh root@your-server
password: admin

This started 45 seconds after your IP was assigned.


It will not stop. Ever.

The Plan

Server → Docker → Network → Application → Authorization → Secrets → Dependencies → Monitoring


Each layer assumes the one above already failed.


Like an onion. Except each layer says "no."

🔒 The Server Layer

(lock the door before buying a camera system)

SSH: No Passwords. Ever.

PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
AllowUsers deploy
MaxAuthTries 3

+ fail2ban = three strikes, banned for an hour

Changing the port to 2222? That's hiding the key under a different rock.

Famous Last Words

"I'm the only one on this server."

"Permissions don't matter."

"We don't need tests for this."


chmod 600 ~/.age-key.txt
chmod 700 ~/.ssh

Least privilege is boring. Boring keeps your data.

Firewall: Be Rude

ufw default deny incoming
ufw allow 22/tcp
ufw allow 443/tcp
ufw allow 80/tcp

Postgres on the internet? Redis on the internet?

Please don't. I've seen the ransom notes.

Updates: The Boring Hero

sudo apt install unattended-upgrades

Most breaches exploit known bugs with patches already available.

The attacker didn't find a zero-day.
The admin didn't run apt upgrade.

🐳 Docker Security

(it's not a VM, stop treating it like one)

Containers Run as Root by Default

Let that sink in.


USER app  # in your Dockerfile

Two words. Container now runs as nobody.

Four extra lines in your Dockerfile. Saves your career.

The Docker Group

docker run -v /:/host -it alpine sh
cat /host/etc/shadow

Full host access. Root with a fake mustache.


Use rootless Docker or Podman instead.

The Padded Room

docker run \
  --read-only \
  --tmpfs /tmp \
  --memory=512m \
  --cpus=1.0 \
  --pids-limit=100 \
  --security-opt=no-new-privileges \
  myapp

Attacker is stuck in a box with no pen.

🌐 Network Layer

(encrypt everything, hide what you can)

TLS: Not Negotiable

It's 2026. It's free. There are zero excuses.

sudo certbot --nginx -d yourdomain.com

"But it's on a private network!"

Networks get misconfigured. Encrypt it anyway.

Make SSH Invisible ✨

# Tailscale/WireGuard, then:
ufw allow from 100.64.0.0/10 to any port 22
ufw deny 22

Port scanners find nothing. Bots go home confused.

Auth.log goes from 10,000 failures/day to zero.

Best day of your sysadmin life.

💻 Application Layer

(where the real disasters happen)

Trust Nobody

class CreateUser(BaseModel):
    name: str = Field(min_length=1, max_length=100)
    email: EmailStr
    age: int = Field(ge=13, le=150)

Client-side validation is decoration.

Attackers don't use your form. They use curl.

SQL Injection: Still in 2026

# 😱 How to ruin your week
f"SELECT * FROM users WHERE name = '{user_input}'"

# 😌 How to not
cursor.execute("...WHERE name = %s", (user_input,))

It's like still having polio. We have the vaccine.

XSS

User submits: <script>stealCookies()</script>

Your template renders it. Session tokens gone.


Jinja2 auto-escapes. But {{ data | safe }}?

You just lied to your template engine.

CSRF

User visits funny cat website.

Cat website submits a hidden form to your bank app.

Browser attaches the session cookie.

Money transferred. Via a cat website.


SameSite cookies. Django CSRF middleware. Use them.

Passwords: Slow Is Good

SHA-256: billions of hashes/second (bad for passwords)

argon2: ~100ms per hash (bad for attackers)


Brute force time: 1 hour → 3,170 years


CryptContext(schemes=["argon2"])

JWTs: Not in localStorage

localStorage is readable by any script on the page.

Any XSS = every user's token stolen.


HttpOnly cookies. Always.

It's like storing your house key in a glass box on the porch.

Rate Limiting

limit_req_zone $binary_remote_addr zone=login:10m rate=5r/m;

5 attempts/min/IP. Kills brute-force dead.


Rate limit: login, signup, password reset, expensive endpoints.

If a user hits your API 1000 times/min, they're probably not a user.

Security Headers: Free Armor

Content-Security-Policy: default-src 'self'
Strict-Transport-Security: max-age=31536000
X-Frame-Options: DENY

CSP blocks injected scripts. HSTS forces HTTPS forever.

Someone left a suit of armor on the ground labeled "FREE."

Most people walk past it.

🔑 Authorization

(the part everyone gets wrong)

Week 1 vs Week 12

# Week 1: beautiful
if user.is_admin: allow()

# Week 12: crying
if user.role == "editor" and resource.team_id == user.team_id:
    if resource.is_shared or user.has_permission("can_approve"):
        if action == "approve" and resource.fiscal_year == ...
# ... spread across 40 endpoints

Fine-Grained Authorization

# OpenFGA model — one source of truth
type document
  relations
    define owner: [user]
    define editor: [user, team#member] or owner
    define viewer: [user, team#member] or editor

Adding a role = model change, not a 40-file code change.

One Call. Any Endpoint.

# Can sara edit this?
check(user="user:sara",
      relation="editor",
      object="document:security-essay")
# → true (she's on the team)

"Who can access this?" → query the model, not grep the codebase.

IDOR: The World's Dumbest Bug

/api/invoices/42 → your invoice

/api/invoices/43 → someone else's invoice


Did you check? Or did you just check "is user logged in"?


FGA: one check() per request. Put it in middleware. Done.

Row-Level Security

ALTER TABLE documents ENABLE ROW LEVEL SECURITY;

CREATE POLICY docs_owner ON documents
    USING (owner_id = current_setting('app.user_id')::int);

App has a bug? Database still won't leak rows.

Defense in depth at the query planner level.

CORS: Not Access-Control-Allow-Origin: *

That lets any website make authenticated requests to your API.

Including the funny cat website.


Whitelist your own domains. Nobody else.

🔐 Secrets

L1: sops + age (encrypt in repo, decrypt at deploy)

L2: GCP Secret Manager (never touches disk)

L3: Vault (short-lived, auto-rotating)


None protect a fully compromised runtime.

That's what the other 9 sections are for.

📦 Dependencies

Bedtime stories:


event-stream (2018): new maintainer stole Bitcoin keys

colors/faker (2022): author self-sabotaged in protest

Pin versions. Commit lockfiles. Trust nobody.

👁️ Monitoring

"Hope" is not an incident response plan.


Ship logs off the box. Attackers clean local logs first.

Alert on: new IPs, CPU spikes at 3 AM, unknown users.


Crypto miners love the night shift.

Incident Playbook

1. Isolate (don't shutdown — you need memory for forensics)

2. Preserve evidence

3. Rotate ALL credentials

4. Find the entry point

5. Patch it

6. Restore from clean state

7. Watch closely for 30 days. They come back.

The Mental Model

Every layer assumes the one above already failed.


The goal: make attacks expensive enough that the attacker goes to bother someone with an open MongoDB on port 27017.

Actually, deploy whenever you want.
